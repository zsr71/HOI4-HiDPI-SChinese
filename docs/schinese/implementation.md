# 中文适配实现与验证边界

## 字体与光晕

HOI4 从 BMFont `.fnt` 与纹理图集读取文字。上游用 2 倍图集及带标记的文字着色器，
在保留逻辑字体度量的同时增加采样细节，并在低分辨率文字缓冲中传递子像素覆盖率。

`build_mod.py` 增加中文路径识别、字体组选择和变量字重实例化。
`hidpi/fontgen.py` 的 `split_atlas` 把中文大图集拆成实际纹理不超过 2048 × 2048 的页面；
字形坐标仍是 1 倍逻辑单位，由 `core_chinese.gfx` 等文件引用拆页结果。
图集标记周围保留 4 × 4 块，减少 DXT5 压缩破坏标记所产生的识别错误。

`FontSpec.solid` 输出白色 RGB 填充，alpha 只表示字形覆盖率。
不能保留带阴影的原版 alpha 并只将 RGB 改白，否则阴影也会变亮，产生光晕、重影。
没有轮廓字形的字符保留填充回退路径，避免直接丢字。

## 最终源补丁

基础生成器中的着色器补丁不包含验收期间的全部最终变更。
最终结果保存在 `schinese/release-patches.json`：

- 原文件从用户安装目录读取，SHA-256 检查游戏基线。
- 未改动行用原文件行区间引用，新增和修改行保存变更文本。
- 重建后检查目标 SHA-256，保持 BOM、编码与换行。
- 两个新增字体别名定义保存完整生成文本。

这是固定基线的精确源变更记录，不是自动适配所有游戏版本的通用补丁。

## 对齐修正

按钮使用独立字体别名修改 `yoffset`，避免全局移动同组字体导致正文受影响。
UI 2.0 时一个逻辑单位对应两个屏幕像素。

| 字体 | yoffset 改变量 |
|---|---:|
| hoi_16mbs | -1 |
| hoi_18mbs | -2 |
| hoi_20b | -2 |
| hoi_20bs | -1 |
| hoi_24header | -2 |
| hoi_30header | -4 |

补丁还保留两组早期居中别名；111 个别名页面的来源、偏移和 SHA-256 均在记录中。
它们只移动 `.fnt` 字形位置，DDS 与基础页面相同。

顶部数字和日期、贸易地区筛选与科学家姓名是独立文本框，按钮字体别名不会覆盖它们。
最终 GUI 修正包括 15 处顶部文字 y 减 2、贸易筛选模板 y 减 2、科学家姓名 y 减 4。

## 可重建性

本仓库保存 Noto Sans SC 字重 600 静态实例：

```text
fonts/NotoSansSC-SemiBold.ttf
SHA-256: 8e56779dc1719ccd8d015fcddfee3dcbf2ccb082cbf07ace3cb4ef518ca42e5a
```

验收包的各组字体经历不同阶段的重绘、压缩/非压缩输出和局部修复；
当前单次基础生成不能保证得到完全相同结果。
最终源变更和哈希清单使结果可追踪与复核，但完整从零重建仍需整理各组参数及中间转换。
输出清单对应已验收的本地运行文件，不代表新生成结果已经游戏内验收。

## 验证和维护

`python -m unittest discover -s tests -v` 检查填充、缺字回退、拆页和补丁版本保护。
补丁工具已按当前安装的游戏基线检查文本输出，字体别名按验收字体复核。
`python -m schinese.verify_release MOD_ROOT` 检查全部验收运行文件，不包括封面及发布文案。
游戏内验收范围为 Windows / HOI4 1.19.3 / DX11 / 3840 × 2160 / UI 2.0。

后续应统一各组生成参数，独立重建并比较哈希，然后冷启动复查地图文字、文字缓冲与按钮位置。
